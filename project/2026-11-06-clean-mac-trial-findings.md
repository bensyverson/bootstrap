# Clean-Mac trials of v0.2.0 and v0.3.0 (2026-11-06)

The end-to-end test for `UyKEjV` (a VM run from nothing) and `QKSluk` (the trial in both apps), using the published v0.2.0 and the bare link. Run from `grace` over ssh to the Mac Mini (`agent@sally.local`), with Tart at `~agent/tart-install/tart.app`. Ben played the new user in the VM over Screen Sharing.

## First run: Claude Code on a Cirrus vanilla clone (stopped at Apple's step)

**Setup.** `trial-cc`, a clone of `ghcr.io/cirruslabs/macos-tahoe-vanilla:latest` (macOS 26.6.2, arm64, 50 GB disk). Gatekeeper on (`spctl --status`: `assessments enabled`), `/etc/sudoers.d/admin-nopasswd` removed, no Apple tools or Homebrew. Caches, Spotlight's index, `uuidtext` and the logs were cleared to reach 19.47 GB free. Claude Code 2.1.318 was installed with `curl -fsSL https://claude.ai/install.sh | bash`, and Ben added its `PATH` line to `~/.zshrc` as the installer says. He started `claude` in a new folder, `~/Claude`, signed in, and pasted only `https://github.com/bensyverson/bootstrap`. Logs: `local/trial-2026-11-06/` (`session.jsonl`, the program's; `cc.jsonl`, Claude Code's transcript).

**What happened, in order:**

1. **The agent reached for `gh`, then `git clone`, before reading anything.** `gh` wasn't there; `git` is Apple's stub on a new Mac, so it raised the "install command line developer tools" dialog, behind Terminal where Ben couldn't see it. The agent then read the README through a web fetch, and later `SETUP.md` with `curl` as told. The agent said the dialog was safe to cancel. (A `python3` in a monitoring command of mine raised the same dialog a moment later: on a new Mac, `python3` is a stub too.)
2. **The consent message was long and technical**, a five-point list with checksums, the team ID and `spctl`, not step 1's short message ending "OK to go ahead, or want the details first?". Every fact in it was right. It opened "That's your bootstrap repo", since Claude Code was signed in as Ben.
3. **Gatekeeper said `rejected`** with `source=Notarized Developer ID` and Ben's team. The agent asked before going on, as `SETUP.md` says. **This is the VM's quirk:** the same download says `accepted` on the Mini itself (macOS 26.6.2, real hardware) and on `grace` (`spctl -a -vvv -t open --context context:primary-signature <file>` on each, 2026-11-06).
4. **The page opened about a second after `run`** (`show welcome` 15:01:06.36, `tabs 1` 15:01:07.61 in `session.jsonl`).
5. **"Got it" flashed.** After the tool list, the flow showed `fast` ("Got it. We'll only stop if we need you.") and replaced it 2 ms later with `chat`, because the Apple step handed off at once (`session.jsonl` seq 13 to 18). Ben saw it as a hitch in the animation.
6. **Apple's step handed off `disk-short`:** "only 18.7 GB is free, and Apple's tools need 20 GB". Free space fell from 19.47 GB to 18.7 GB between preparing the VM and the check, mostly Claude Code's auto-update to 2.1.319, which left 2.1.318 (305 MB) behind. The program asks for 20 GB; Apple's own floor is 19.18 GB ([the VM runs](2026-11-05-vm-run-findings.md)).
7. **The agent handled the handoff well.** It looked for caches, Trash and Downloads to clear, found nothing safe, said the 20 GB is a cautious margin, and offered: free about 1.5 GB yourself, make the disk bigger if it's a VM, or stop.

**Why the run stopped.** The image's disk can't grow in place: `tart set --disk-size` adds space behind the recovery partition, which SIP won't let `diskutil` move. `/System/Library/AssetsV2` (1.3 GB) is SIP-protected too. Ben chose a new VM from Apple's installer with a 100 GB disk (`tart create --from-ipsw latest --disk-size 100 trial`), and the four spent VMs (`clt3`, `fresh`, `spike`, `trial-cc`) were deleted.

## Second run: Claude Code on a VM built from Apple's installer (reached done)

**Setup.** `trial`, made with `tart create --from-ipsw latest --disk-size 100 trial` (macOS 26.6.2, 25G83), so its disk is laid out at full size. Ben clicked through Setup Assistant (account `admin`, no Apple Account) and turned on Remote Login; nothing else was changed. Gatekeeper on, `sudo` asks for a password, no Apple tools or Homebrew, 67 GB free. Claude Code was installed and put on `PATH` as before; Ben switched the model to **Sonnet 5.5** (the first run was Opus 5.5), started in `~/Claude`, and pasted the bare link. Tart's VNC has no shared clipboard, so text went onto the VM's clipboard over ssh (`launchctl asuser 501 sudo -u admin pbcopy`). Logs: `local/trial-2026-11-06/run2/`.

**It reached done.** Every picked tool installed as a bottle, each in 4 to 12 s (`session.jsonl` seq 31 to 43); Homebrew's `.pkg` took Ben 18 s to click through. After each click the next screen was shown within about 70 ms. Auto mode needed nothing beyond the chat yes; the agent ran `bootstrap` outside Claude Code's sandbox on its own. The agent's ending was right: a sum-up, `/remote-control` for later, `/exit`, Command-N, the two lines, and `bootstrap new` for later projects. Ben restarted as told, and the new session found the tools by name and loaded `AGENTS.md`.

**Findings, most serious first:**

1. **Raising Apple's window made the step fail.** `xcode-select --install` started the installer, then `open -a '…/Install Command Line Developer Tools.app'` 50 ms later exited 1 ("Launch failed", launchd error 162) while the app was still starting. The flow treats that as trouble, so it handed off and sent Ben to Terminal. The same `open -a`, run once the installer was up, exited 0 and brought the window forward, twice, with no permission prompt. **Fix:** wait for the installer's process, retry `open -a`, and never fail the step over it.
2. **With the step handed off, the agent improvised.** It ran `osascript … System Events … set frontmost`, which raised macOS's "Terminal wants access to control System Events" prompt (Ben declined), then waited 90 s and handed the turn back: "Tell me when you've clicked Install". Finding 1 removes the cause; `SETUP.md` should also forbid scripting other apps, and have a trouble handoff whose cure is a click keep checking in a loop.
3. **The fetch tool refused to give `SETUP.md` whole** ("I won't reproduce the full SETUP.md verbatim"), so Sonnet's first message was a generic "run it, review it, or something else?" rather than step 1's consent message. Once Ben said "run the setup", it read the file with `curl` and followed it. The README should name `curl -fsSL` for the raw file, not only say "raw". The agent also tried `gh` first again.
4. **A second run reverses a decline and blocks on a person.** `bootstrap new --yes` in `~/Projects/blammo` skipped every finished step, then took GitHub's default (yes) though Ben had said not now on the page, installed `gh` 2.103.3, and started `gh auth login`, waiting for a code no one would enter. It was stopped; `gh` was the only change (`snap.sh` diff before and after). Ben, 2026-11-06: the headless setup should remember the person's answers, with a way to update them.
5. **Working screens flash.** `fast` ("Got it…") showed for under 70 ms before `apple-ask`, and `building` ("Setting up your project") for 6 ms before `git-ask` (seq 12 to 15, 54 to 58). Ben read both as glitches. One fix in the page: hold back a working screen briefly, and skip it if another screen arrives first.
6. **The question layout overlaps the percentage** on `git-ask`, `github` and `settings` at the VM's Safari window size: the question sits too low and the percentage runs into it.
7. **The setup assumes a project.** Ben: someone may want only the tools. The naming screen needs a way to skip the project steps (folder, Git, rules, making) while keeping the machine-wide ones (GitHub, Git identity, helpers, phone).

The Gatekeeper `rejected` of the first run didn't recur: this VM says `accepted`, which confirms it was the Cirrus image's quirk.

## Third run: v0.3.0 with Claude Code, on a clone of the base VM (reached done)

**Setup.** `trial-base` was made like the second run's VM (`tart create --from-ipsw latest --disk-size 100`, macOS 26.6.2, 25G83). Ben did Setup Assistant (account `admin`, no Apple Account, Remote Login on), and it was stopped and never run again. This run used `trial-cc1`, a `tart clone` of it, with 63 GB free. Claude Code 2.1.319 was installed over ssh with `curl -fsSL https://claude.ai/install.sh | bash` and put on `PATH`. Ben started `claude` in `~/Claude` on **Opus 5.5** in auto mode (`cc.jsonl`: `"permissionMode":"auto"`, `"model":"claude-opus-5-5"`), signed in, and pasted the bare link. v0.3.0 had been released minutes before, so SETUP.md pinned it. Logs: `local/trial-2026-11-06/run3/` (`session.jsonl`, `cc.jsonl`, `clt.log`, `bootstrap.log`, `preferences.json`).

**It reached done in under 9 minutes**, from the welcome screen at 10:45:22 to done at 10:54:06 (`session.jsonl` seq 4 to 113). Apple's tools took 6 min 23 s from the click to installed (seq 17 to 32), Homebrew's `.pkg` 20 s (seq 35 to 38), and the six tools 4 to 12 s each. There was no trouble, and the only handoff was done. The agent checked the sha256, the signature and the notarization, started `run`, waited in 90 s turns, and summed up at the end, listing "bootstrap itself" among the tools.

**What this run settled:**

1. **Apple's and Homebrew's windows came to the front** on their own (Ben, watching). The second run's finding that Apple's window opened behind the browser is fixed by `6374e0f`. Ben saw no dialog before the welcome screen, so the window was the setup's own.
2. **bootstrap moved onto Homebrew as designed** (`wz9ORc`). After the tools, `brew install bensyverson/tap/bootstrap` poured the 0.3.0 bottle (`bootstrap.log`), and the run noted `installed bootstrap 0.3.0` and `deleted ~/.bootstrap/bin/bootstrap; /opt/homebrew/bin/bootstrap runs from now on` (seq 54, 55). The agent's next `wait` was `/opt/homebrew/bin/bootstrap wait`, as the `next:` line said, and Claude Code asked for no approval (Ben). Afterward `~/.bootstrap/bin` was empty and `/opt/homebrew/bin/bootstrap --version` said 0.3.0.
3. **No working screen flashed** after the tool list or naming (Ben), matching his check of the demo page (`a6Q6ie`).

**Findings:**

> **Corrected, 2026-11-06 (Ben):** no dialog appeared before the welcome screen, so the window that came to the front was the setup's own, and the early `git clone` showed nothing to the person. Why Apple's stand-in printed its message without a dialog showing is not established. The finding below stands only as "the agent tries `gh` and `git` first".

1. **Before reading anything, the agent ran `git clone`, which pops Apple's dialog on a clean Mac.** Its first moves on the bare link were `gh repo view` (`command not found`) and then `git clone --depth 1 https://github.com/bensyverson/bootstrap.git` into its scratchpad. Apple's stand-in `git` printed "…cancel the installation dialog", so the "install the command line developer tools?" dialog opened about 50 s before the setup asked for it. Then the agent fell back to `curl` on the GitHub API and the raw SETUP.md, as the README says. The README can't prevent this, because the agent acts before it reads the README. Whether the window Ben saw come to the front was this early dialog or the setup's own is not settled. Ben wasn't sure when it first appeared, and the setup's `xcode-select --install` still reported "install requested" and exited 0 (`clt.log`). It did no harm here: clicking Install on either dialog installs the same tools, and the setup's check finds them. The second run (Sonnet 5.5) didn't do it. Filed in `job`.
2. **The new tool line** came out of this run: Ben asked for "Standard developer tools, including Git." instead of "Apple's tools, which include Git." (`977f655`, for the next release).
